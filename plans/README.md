## Findings considered and rejected / deferred

- **UTC day-boundary mismatch in `syncSRSSchedule` overlap queries**
  (`src/lib/calendar.ts:94-95` uses `T00:00:00Z`–`T23:59:59Z` windows while
  events are created in local time): rejected — works correctly for all
  events the app itself creates (09:00 local falls inside the UTC window
  for UTC±12); only manually-moved calendar events near midnight could be
  missed, and the next sync self-heals. Not worth the timezone-handling
  complexity.
- **Only `existingEvents[0]` is updated when multiple app events overlap a
  day** (`src/lib/calendar.ts:104`): rejected — requires the user to
  manually duplicate app events in Google Calendar; rare and self-healing.
- **`alert()` used for error display** (`src/App.tsx:134`,
  `src/components/Dashboard.tsx:109,155`): deferred — cosmetic UX debt, low
  leverage; a toast/inline-error redesign should be a deliberate UX pass,
  not a drive-by.
- **OAuth error page interpolates `error.message` unescaped into HTML**
  (`server.ts:213`): deferred — the interpolated text originates from
  Google's token endpoint, giving an attacker little control over content;
  noted in plan 001's maintenance notes as a follow-up escape fix.
- **`npm audit` transitive advisories** (body-parser, postcss, nanoid,
  @babel/core, esbuild — all fixable via `npm audit fix`): deferred — a
  lockfile-wide bump deserves its own verification run; plan 005's
  maintenance notes point at it.
- **No AGENTS.md / CLAUDE.md**: deferred — repo is small and
  self-describing; revisit if agent-driven contributions become frequent.
- **Direction findings** (not problems, options for the maintainer):
  - The `metadata.json` + README lineage shows this started as an AI Studio
    / Gemini app but no AI feature survives in code. If statute explanation
    or quiz generation was ever intended, the `@google/genai` removal in
    plan 005 should be reconsidered as "wire it up" instead of "delete" —
    a product decision, not a code one.
  - The app is purely client-side against Google Calendar; a lightweight
    server-side token refresh flow (the server already has the client
    secret and requests `access_type: 'offline'`) would fix the ~1-hour
    token expiry that currently forces re-login. Grounded in
    `server.ts:101-104` + `src/lib/auth.ts`. Medium effort, real UX win.
